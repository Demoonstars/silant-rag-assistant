# 🚜 СИЛАНТ — Интеллектуальный сервисный RAG-ассистент (ООО «ЧЗСА»)

Прототип информационно-поискового RAG-сервиса по эксплуатационной документации вилочных погрузчиков **«СИЛАНТ»** производства Чебоксарского завода силовых агрегатов (ООО «ЧЗСА»).

Сервис предназначен для механиков сервисной службы и операторов техники: позволяет за 5–15 секунд находить точные регламенты ТО, заправочные объемы и марки ГСМ, моменты затяжки, коды ошибок контроллеров и пошаговые процедуры с сохранением всех предупреждений безопасности и указанием точного первоисточника (документ, раздел, таблица, страница).

---

## 1. Поддерживаемая техника в базовой поставке

База знаний построена по официальным руководствам по эксплуатации ООО «ЧЗСА»:

1. **Автопогрузчики вилочные с ДВС (`РЭ Автопогрузчики с измен. АРМ+ (58 стр).pdf`):**
   - **Дизельные (серия ПД):** `ПД1,5`, `ПД1,8`, `ПД2,0`, `ПД2,5`, `ПД3,0`, `ПД3,5` (ДВС Kubota) и тяжелая модель `ПД5,0` (ДВС ММЗ Д-243 с индивидуальной сеткой ТО: `125 / 250 / 500 / 750 / 1000 / 1500 м/ч`).
   - **Газобензиновые (серия ПГ):** `ПГ1,5`, `ПГ1,8`, `ПГ2,0`, `ПГ2,5`, `ПГ3,0`, `ПГ3,5`.
2. **Электропогрузчики (`ПЭ15-00.00.000_РЭ (02.04.25).pdf`):**
   - **Электрические (серия ПЭ):** `ПЭ1,5`, `ПЭ1,8`, `ПЭ2,0`, `ПЭ2,5` (сетка ТО: `ЕТО 50 / ТО-0 100* / ТО-1 250 / ТО-2 1000 / ТО-3 2000 / ТО-4 4000 м/ч`).

> При загрузке дополнительных PDF-руководств через веб-интерфейс система автоматически распознает новые модели техники и добавляет их в выпадающее меню выбора.

## 2. Архитектура и ключевые технические решения

- **Структурный парсинг PDF и таблиц (`parser.py`):**
  - Используется библиотека `pdfplumber` с геометрическим разделением координат таблиц (`bbox`) и основного текста страницы, что исключает дублирование строк.
  - Автоматическая фильтрация боковых и нижних рамок штампов ГОСТ (`Инв. №`, `Подп. и дата`, `Изм. Лист`), спецсимволов шрифтов Wingdings и исправление вертикально повернутых заголовков колонок.
  - Перевод многоэтажных заводских таблиц (заправочные объемы ГСМ, контрольные листы ТО, моменты затяжки колесных гаек, коды ошибок контроллеров) в чистую разметку Markdown со склейкой разорванных на стыках страниц процедур.
- **Локальная векторизация и гибридный поиск (`indexer.py`, `rag_engine.py`):**
  - **Векторная база данных:** `ChromaDB` на базе локальной мультиязычной модели эмбеддингов `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (индексация всех руководств занимает 3–5 секунд на CPU без квот и лимитов облачных API).
  - **Гибридный поиск (`BM25` + `ChromaDB`):** объединяет лексический поиск `BM25Retriever` (для точного нахождения артикулов, марок жидкостей `МГЕ 46В`, `Dextron III`, `Д-243`, резьбы `6М20х1,5`, кодов ошибок) и семантический векторный поиск `ChromaDB` с предварительной фильтрацией по выбранной модели погрузчика.
- **Генерация ответа без VPN и защита от галлюцинаций (`rag_engine.py`):**
  - Работает с российских IP-адресов без VPN через `OpenRouter API` / `DeepSeek API` (с автоматическим резервированием через `Google Gemini API`).
  - Нулевая температура генерации (`temperature=0.0`) и жесткий системный промпт: запрет использования внешних знаний, автоматический запрос уточнения модели при неоднозначности и 3 сценария честного отказа (данных нет в РЭ вообще / данные только для другой модели с запретом переноса / вопрос относится к отдельной инструкции на двигатель или АКБ) с выводом контактов сервисной службы ООО «ЧЗСА».

## 4. Установка и запуск

### 4.1. Подготовка виртуального окружения

Требуется установленный **Python 3.10 – 3.12**. Откройте терминал в папке проекта и выполните:

~~~bash
python -m venv venv

# Активация окружения в Windows (PowerShell):
.\venv\Scripts\Activate.ps1

# Активация окружения в Linux / macOS:
source venv/bin/activate

# Установка зависимостей:
pip install -r requirements.txt
~~~

### 4.2. Настройка ключей API

Создайте в корне проекта файл `.env` (по образцу `.env.example`) и укажите бесплатный ключ `OPENROUTER_API_KEY` (получается за 30 секунд на сайте [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys), работает в РФ без VPN):

~~~env
OPENROUTER_API_KEY=sk-or-v1-ваш_ключ
DEEPSEEK_API_KEY=
GEMINI_API_KEY=
~~~

### 4.3. Первичная сборка базы и запуск веб-интерфейса

Если векторная база в папке `data/chroma_db` еще не создана, запустите индексацию руководств (выполняется ~5–10 секунд):

~~~bash
python indexer.py
~~~

Запустите веб-приложение:

~~~bash
python -m streamlit run app.py
~~~

Веб-интерфейс автоматически откроется в браузере по адресу `http://localhost:8501`.

## 5. Процедура обновления базы знаний (добавление и удаление PDF)

Обновление эксплуатационной документации не требует изменения исходного кода и выполняется любым из двух способов:

### Способ 1. Через веб-интерфейс (в режиме реального времени)
1. В левой боковой панели откройте сворачивающуюся вкладку **«📂 2. База PDF»**.
2. **Добавление нового руководства:** перетащите один или несколько PDF-файлов в поле *«Добавить новое PDF-руководство»*. Система автоматически прочитает текстовый слой и таблицы, выявит новые индексы моделей, запишет векторы в `ChromaDB` и сразу обновит выпадающий список моделей.
3. **Удаление руководства:** нажмите кнопку **`✕`** справа от карточки нужного файла — его страницы, векторы и модели будут мгновенно удалены из базы знаний.
4. **Полная переиндексация:** при необходимости перечитать все PDF-файлы с нуля нажмите кнопку **«🔄 Полная пересборка базы»**.

### Способ 2. Через папку `data/manuals` и терминал
1. Поместите новые PDF-руководства (с текстовым слоем) в папку `data/manuals/` или удалите устаревшие файлы.
2. Запустите команду пересборки индекса:

~~~bash
python indexer.py
~~~

## 6. Проверка на эталонном тестовом наборе вопросов (Gold Standard)

В проект включен скрипт автоматического тестирования `evaluate.py`, содержащий **10 контрольных сценариев** по требованиям ТЗ:
- вопросы по регламенту ТО и ГСМ тяжелой модели `ПД5,0` (ДВС ММЗ Д-243);
- пошаговая процедура замены колес ведущего моста, требования к домкрату и моменты затяжки (`ПД3,0`);
- диагностика по контрольным лампам (`ПД2,0`) и кодам ошибок контроллера (`ПЭ1,5`);
- обслуживание газобаллонного оборудования (`ПГ2,5`) и правила зарядки тяговых АКБ (`ПЭ2,0`);
- проверка автоматического уточнения модели при неполном запросе (`Не выбрана`);
- 3 типа вопросов без ответа в базе (отсылка к отдельной инструкции на ДВС, запрет переноса данных с другой модели и полный отказ с выводом контактов сервиса ООО «ЧЗСА»).

Для запуска автопроверки и формирования отчета выполните:

~~~bash
python evaluate.py
~~~

По завершении скрипт сохранит детальный отчет со сличением эталонных и фактических ответов в файл **`test_results.md`**.

| Показатель тестирования | Значение | Требование ТЗ |
| :--- | :---: | :---: |
| Всего контрольных тест-кейсов | **10** | Полное покрытие семейств ПД / ПГ / ПЭ и отказов |
| Успешно пройдено сценариев | **10 из 10 (100%)** | Отсутствие галлюцинаций и смешивания моделей |
| Среднее время ответа | **16,2 сек.** | До 60 сек. |

## 7. Текущие ограничения сервиса

1. **Текстовый слой PDF:** парсер рассчитан на PDF-документы с текстовым слоем. При попытке загрузить бумажный скан без OCR система вежливо уведомит пользователя и отменит загрузку пустого документа.
2. **Графические диаграммы и схемы:** кривые на графических нагрузочных диаграммах (Раздел 15) и принципиальные гидравлические/электрические схемы снабжаются текстовым примечанием с точной ссылкой на страницу, где механик может посмотреть сам чертеж.
